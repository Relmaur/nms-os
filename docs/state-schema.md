# State schema & merge rules (`nms_state.json`)
The application state MUST be serializable to and from `nms_state.json` (the shared copy lives at `apps/web/public/nms_state.json` and is published at the site root).
- On load, the app attempts to `fetch('./nms_state.json')` to hydrate initial state, merging with `localStorage.getItem('nms_master_os_state')`.
- Provide an **"Export nms_state.json"** button and **"Import nms_state.json"** file dropzone in the top header.

## Default `nms_state.json` Schema:
See [`nms_state.json`](../apps/web/public/nms_state.json): the canonical default (identical to `DEFAULT_STATE`, a test checks), and a new player's starting point. Since 3.14.0 it holds nobody's save: no ships, notes, systems, checklist ticks or phase.

The shape every export and import follows:

- `meta` — `version`, `lastUpdated`, `platforms`, `currentPhase` (optional; Home and Book I show it only when set)
- `fleet` — legacy (before 3.14.0): free-form notes `{ primaryStarship, salvageStarship, multiTools[] }`. Kept and carried along untouched; read once by the `gear` migration.
- `gear[]` (3.14.0, ADR-0007) — the player's ships and Multi-Tools: `{ id, kind (starship|multitool|exosuit, the last since 3.16.0; anything else loads as starship), name, class (empty for an Exosuit), type, role, superchargedSlots: ["R2C3", …], slotLabels: { "R2C3": "Infra-Knife" } (3.14.3; kept only for marked slots, up to 40 characters), notes (Markdown), createdAt }`. A log without `gear` (missing or null) gets its `fleet` converted by `gearFromFleet()` (`packages/core/src/gear.ts`) with fixed ids (`fleet-flagship`, `fleet-spare`, `fleet-tool-<n>`) and a fixed `createdAt`, so two devices that migrate separately produce identical records; an emptied list (`[]`) stays empty. A damaged entry is dropped, not the log.
- `checklists` — flat map of `id -> boolean` (named milestones such as `crossSaveLinked`, plus guide checklist item ids such as `cs1`, `rm3`)
- `systems[]` — `{ id, name, galaxy, region, glyphs (12 hex or ''), star (yellow|red|green|blue|purple|''), race (gek|korvax|vykeen|none|abandoned|''), economy, wealth (0–3), planetCount (0–15, 0 = not logged; added in the redesign, missing reads as 0), conflict (low|medium|high|pirate|''), tags: string[], favorite, rating (0–5), notes, planets: [{ id, name, biome, tags, notes }], visits: [{ at: ISO, note?, packets? }], createdAt }`. Tags are lowercase slugs (`trade-hub`).
- `outlaw` — `{ restockHours, packetsPerVisit, runSize, unitsPerPacket, nanitesPerPacket }`. The last two are the player's own in-game averages (packet prices and contents aren't fixed game data). Outlaw stations are systems tagged `outlaw`; one counts as ready once `restockHours` have passed since its last visit with `packets`. `runStartedAt` (ISO, optional, added in the redesign) is the run in progress: it covers the packet runs logged since, and ends once `runSize` stations are done or `restockHours` have passed (`outlawProgress` in `packages/core/src/outlaw.ts`). Anything but a time is dropped on load.
- `timers[]` (3.9.0) — `{ id, kind (refine|crop|custom), label, startedAt: ISO, endsAt: ISO, alerted }`. A refiner timer's length is the wiki's refining time (`seconds` per unit made, over the units of whole batches); a crop's or a custom timer's is the player's own. `alerted` marks a finish already announced, so a reload or another tab never announces it twice. Finished timers stay until dismissed.
- `session` (3.9.0) — `{ startedAt: ISO, timersDone } | null`: the play session in progress. `sessions[]` — `{ startedAt, endedAt, timersDone }`, the last 50 ended. A recap is computed from the log inside the window (visits, new systems, packet runs at the outlaw averages); only `timersDone` is counted as it happens, since a dismissed timer leaves the list.
- `notes[]` (3.14.0, ADR-0007) — the player's own notes: `{ id, title, body (Markdown, up to 100,000 characters), pins: ('home'|'book1'…'book6'|'gear:<gear id>')[] (a gear pin, added in the redesign, links the note to that ship, Multi-Tool or Exosuit: it lists on its screen; a pin to removed gear is dropped when the gear is removed), tags: string[] (lowercase slugs like a system's, up to 12; added in the redesign, missing reads as none), createdAt, updatedAt }`. Pins and tags merge as sets in sync. Rendered through a strict allowlist (`apps/web/src/ui/parts/safe-html.ts`): no images, styles, ids or non-http(s) links.
- `devices[]` (added in the redesign) — the devices that sync this log: `{ id, name ("iPhone · Safari", from the browser's own description, up to 60 characters), lastSync: ISO }`, up to 20. Each device writes only its own entry, at most hourly, when it syncs (`stampDevice` in `packages/core/src/devices.ts`), so the list travels inside the sealed copy and the relay learns nothing new (ADR-0005). Its id is kept apart from the sync settings (`nms_master_os_device`, this device only) so turning sync off and on doesn't list it twice. A record, not a control: every device shares one code, so dropping one means starting over with a new code. Missing reads as none.
- Legacy keys `logbook[]` and `outlaw.stations[]` are migrated into `systems[]` by `migrateToSystems()` (`packages/core/src/systems-model.ts`) on load and import; ids are kept so re-merging never duplicates.

## Merge rules
- **Sync (ADR-0005, opt-in):** a three-way merge (`mergeStates()` in `packages/core/src/sync.ts`) of this device's copy, the cloud copy, and the copy both last agreed on (`localStorage` key `nms_master_os_state.synced`). Records merge by key (`id`; visits by `at`; past sessions by `startedAt`), tags as sets; a removal wins over an untouched copy, an edit over a removal, and a value changed on both sides goes to the copy with the later `meta.lastUpdated`. Lists without unique keys are taken whole from that copy. The result is validated and built like any other copy. Sync settings (`nms_master_os_sync`: the sync code, the cloud version, the last sync time) belong to the device and are never part of `nms_state.json`; so do the push alert settings (`nms_master_os_push`: a random device id and token, ADR-0006). Two small conveniences stay on the device too, outside the log: the recipe planner's ticks (`atlas_plan_progress`, `docs/calculators.md`) and the last five things opened from search (`atlas_search_recent`: a kind, an id and a title each).
- Precedence: built-in defaults ← `nms_state.json` ← `localStorage`. The device's own log always wins: since 3.14.0 the repo file is only a new device's starting point (before, a newer repo file outranked the browser copy).
- Objects merge key-by-key; arrays (`systems`, `gear`, `notes`, slot lists) are replaced wholesale.
- Data from the pre-2.0 key `ATLAS_MASTER_OS_STATE_V2` (`checkedItems` / `logEntries`) is migrated automatically on load and on import.

## Validation and failure handling (`packages/core/src/schema.ts`, `apps/web/src/app/store.js`)
- `validateState()` parses the document with a Zod schema (`StateDocumentSchema`): it checks the type of every key that is present; missing keys are fine (`buildState()` fills defaults) and unknown keys are allowed, so older and newer exports both load. Errors name the path, e.g. `systems[1].name must be text`.
- **Import** validates the whole file first; an invalid file is rejected with the first problems in the toast, and nothing is replaced.
- **Startup:** a browser copy that isn't JSON or fails validation is kept under `nms_master_os_state.corrupt-<ISO time>` before the app falls back to defaults + the repo file, and a banner says so. Nothing is deleted.
- **Save:** if `localStorage` refuses a write (quota, private mode), the state stays in memory and a persistent banner offers an export; the next successful save clears it.
- **Multiple tabs:** a `storage` event adopts the other tab's saved copy and re-renders, so the last write is always made on fresh data (last-write-wins, ADR-0002).
- **Timeouts:** `nms_state.json` 5 s (the browser copy renders without it), `wiki/index.json` 8 s (then the bundle), `wiki/game-data.json` 20 s, `verification.json` 5 s.
- Diagnostics are one `console.warn('[atlas]', { event, reason })` line, never state contents.
